# Vite+ installation inherits pnpm's `use-node-version`

This repository reproduces an extra Node.js download attempt during first-start
setup of the published Vite+ `1.5.0` release. A user's npm configuration can make
the installer's pnpm fetch another Node.js version before installing dependencies.

Vite+ `1.5.0` was published on November 4, 2026 and was the latest stable release
checked on November 6, 2026. Its installer uses Node.js `24.22.2` and pnpm
`10.34.7`. The reproduction adds `use-node-version=22.18.0` to an isolated user
`.npmrc`.

The behavior exists in the released installer independently of PR #3233. The
reproduction uses the published binary, with `VP_ENV_FORBIDDEN` and the
installation-lockfile bypass unset.

## Run

Requires Python 3.10 or later on macOS or glibc-based Linux, on ARM64 or x64,
plus internet access for the initial artifact downloads. The recorded run used
macOS ARM64; the Linux paths have not been run locally. Run from this repository:

```sh
python3 reproduce.py
```

The script downloads official release artifacts, verifies their integrity, and
caches them in `.artifacts/`. Subsequent runs can reuse this cache. Each case runs
with its own temporary home, Vite+ installation, pnpm directories, and npm
configuration. Your existing configuration, caches, and shell PATH are unchanged.

To retain the temporary case directories for inspection:

```sh
python3 reproduce.py --keep
```

## Expected result

The script reports the release and toolchain versions, checks both cases, and
prints `REPRODUCED` when the observations match:

| Case | User configuration | Expected HTTP requests |
| --- | --- | --- |
| Control | No `use-node-version` | Dependency requests, with no Node.js request |
| Configured | `use-node-version=22.18.0` | `/node/v22.18.0/SHASUMS256.txt` |

A local HTTP server records requests and returns `404`. Both child Vite+
processes therefore exit with code `1` by design. The reproduction script exits
with code `0` only when the control reaches dependency requests without fetching
Node.js and the configured case requests the additional runtime's checksum file.

This demonstrates a download **attempt**. The local server stops it before a
Node.js archive is downloaded.

## How it isolates the behavior

The script preloads the genuine published Node.js and pnpm artifacts into each
temporary Vite+ cache. This avoids the installer's ordinary bootstrap downloads,
so an extra Node.js request can be attributed to pnpm reading the user setting.
The executables are real; they are not test doubles.

It then runs the released `vp` binary through first-start setup. The real
`vp-install-lock.yaml` stays beside the binary, and the installer retains its
normal frozen-lockfile dependency installation. The two cases differ only in
the `use-node-version` setting.

The released installer invokes its pinned Node.js with `pnpm.cjs` and passes the
user's npm configuration to that process. pnpm can consequently act on
`use-node-version` even though Vite+ has already selected its installation
runtime. See the [released installation code](https://github.com/voidzero-dev/vite-plus/blob/671b5e46e228a45346dd82ff1b1517c3730435a7/crates/vp_setup/src/install.rs)
and [pnpm bootstrap code](https://github.com/voidzero-dev/vite-plus/blob/671b5e46e228a45346dd82ff1b1517c3730435a7/crates/vp_pm_cli/src/package_manager/bootstrap.rs).
